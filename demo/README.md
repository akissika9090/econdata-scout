# Demos (offline)

No demo calls an API or needs a key or network access.

## Default mode: saved-result replay, not re-verified

```bash
python demo/replay.py normal
python demo/replay.py review
python demo/replay.py fallback
python demo/replay.py official   # V2: official-site check
```

### Reading `official`: start with one complete path

The report opens with **Main data by paper**: for each paper, the data the authors analysed as main data, with the source sentence and page, and one line on where the official-site check got to. Main-data candidates whose evidence did not pass the checks would appear there under "To verify", with what is missing (none in this run). The merged summary with the two-column tables follows.

Then read one data source end to end: **Kahn & Li (2020), "Online transcripts of judicial decisions"** (first in Kahn2020's main data).

1. **Paper column.** The paper's main data, with page and quote (p. 4: "Our main data source is online transcripts of judicial decisions."), and the years used (2014–2017, p. 4). The paper says nothing about how to get it.
2. **Official-site column.** The check found China Judgements Online (wenshu.court.gov.cn, a government domain). The page says logged-in users can download decisions, so the channel is "free download after registration". The quoted sentence was checked word for word on the page.
3. **What it does not claim.** The page does not mention 2014–2017, so the report says coverage of the paper's years is pending.

Without the tool you would read the data section, find the provider, search its site and the download rules, and note the page; the report puts the quote, page, link and date in one place. The other sources follow the same layout. Some are wrong or incomplete: see "Known errors" below.

In default mode nothing is re-checked. `normal` and `review` print report files that were generated earlier. Each file's first line says when it was generated, by which command, and from which saved model output. `fallback` reads the saved run record. The `demo/data/` files are copies of the originals; the only change is that the paper abstracts from OpenAlex were removed from `fallback/run.json` and `fallback/candidates.json` (the demo does not use them). `demo/data/SOURCES.sha256` lists the checksums of the files as distributed.

## Optional mode: re-verify with local PDFs

```bash
python demo/replay.py normal --reverify    # needs demo/pdfs/yip2018.pdf
python demo/replay.py review --reverify    # needs demo/pdfs/Liebman1998.pdf
```

This mode re-runs verification and report generation with the code in this repository, and rewrites `demo/outputs/<case>.md`. The PDFs are not distributed. If a PDF is missing, the demo reports `SKIPPED` (exit code 77) and changes nothing.

## Known errors and what is not shown

- `official` (checked by hand on 2026-11-18; the report was not edited):
  - **Population census** (fixed by v2.5d): in the run it was shown as "public download, covers the paper's version" on the strength of a 2010 census population table in the statistical yearbook, whose quoted sentence says nothing about how to obtain data. Under v2.5d it is a lead with the next step. An earlier run on the same paper found the microdata application page (institution must apply), but the paper may have used published tabulations, so which product applies still needs checking. Results vary between runs.
  - **Air pollution (Ministry of Ecology and Environment)** (fixed by v2.5d): "public download" rested on a sentence that real-time readings are published. In this report that finding belonged to the removed duplicate; the remaining record shows no verified route and leads.
  - **MERRA-2** (v2.5d): the quoted sentence was "If you have a question, please read …", which does not say how to obtain the data, so it is shown as a lead. The data are in fact distributed by NASA GES DISC; the check did not quote the sentence that says so.
  - **Baidu Index** is labelled a distributor although index.baidu.com is Baidu's own product: the "data's own domain" rule needs an exact name match. The same gap rejected cnemc.cn and data.cma.cn pages in other runs (official institutions without a government domain).
  - **Chang et al.: the main data (Ctrip call-centre worker output) was missing in the run and is restored by v2.5c.** The model had listed it as main data, with the source quote "Our data on worker productivity come from Ctrip International, China's largest travel agency." (p. 5). The sentence is on p. 5, but the PDF has a curly apostrophe (China’s) and the quote a straight one, and quote verification under v2.5b did not treat them as equal. v2.5c treats curly and straight quotes as the same character. The saved model answers were re-verified offline with v2.5c; the official-site check was not run for this source, so its column says "not checked". Its access category stays "not confirmed": the model's access quote does not support "restricted".
  - **Duplicate removed**: in the run, a hand-uploaded second copy of Kahn (2020) was analysed as a separate paper ("used by 2 papers"). It was removed from the saved results offline (no API call). `scout.py` now matches uploaded PDFs to the search results by DOI or full title and skips duplicates.
  - Quotes in the "Official site now" column are copied from the pages on the date checked; pages change.

- `review`: the model missed several data sources in Liebman 1998 (the restricted CPS–tax-return matched file, the 1988 IRS non-filer study, the March CPS 1985–1997 and 1993). These are known limitations.
- `fallback`: the data-source section of that run is deliberately not shown. That run used an older prompt without a usage-relation field, and its report lists data from Dell et al. as used by Bowen 2011, although the paper only cites it. With the current prompt the same paper is handled correctly. The historical result was not edited.
- Two fallback paths have no real saved occurrence, so they are covered only by offline tests (`test_scout.py` for the extraction failure; the Agent error is tested only in the author's development copy, which is not distributed): an extraction failure (all models busy) and an Agent error.
